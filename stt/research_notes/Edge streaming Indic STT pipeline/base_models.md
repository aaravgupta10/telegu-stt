## Q1. Is there an existing streaming-capable checkpoint that covers Hindi + Telugu (+ English) that we could start from, and what is the cheapest credible path to streaming?

### Takeaway
There is no officially released checkpoint I could verify that is (a) cache-aware streaming, (b) covers both Hindi and Telugu, (c) <=600M, and (d) clearly commercially licensed. Two near-misses exist: ARTPARK-IISc **SraVaani-0.5-live** (streaming, Hindi+Telugu, ~430M, MIT but gated, CTC only, Telugu WER 30-35 in streaming) and **NVIDIA Nemotron 3.5 ASR streaming 0.6B** (streaming, Hindi good, **no Telugu**, but explicitly fine-tunable and openly licensed). The cheapest credible path is: start from Nemotron 3.5 streaming 0.6B (adds Telugu via fine-tune) or from SraVaani-0.5-live / Vaani-FastConformer-Telugu / IndicConformer offline encoders, and do cache-aware, multi-lookahead FastConformer training (NVIDIA-documented recipe).

### Cited Findings
- SraVaani-0.5-live (ARTPARK-IISc): cache-aware FastConformer encoder with CTC head, derived from a ~430M hybrid TDT-CTC FastConformer; 17 encoder layers, d_model 1024, 8x subsampling, 128-dim log-mel; 5,000-piece SentencePiece BPE covering Indic scripts + Latin; MIT; **gated** (must share contact info); fp16 TorchScript ~900MB; needs `trust_remote_code=True`, no NeMo required; no ONNX mentioned; claims "real-time-safe" on CPU but gives no CPU numbers; 63 Indian languages incl. Telugu. — [HF: SraVaani-0.5-live](https://huggingface.co/ARTPARK-IISc/SraVaani-0.5-live)
- SraVaani-0.5-live streaming configs: [70,13] 1.12s chunk/1040ms lookahead (default); [70,6] 0.56s/480ms (recommended balance); [70,1] 0.16s/80ms; [70,0] 0.08s/0ms. — [HF: SraVaani-0.5-live](https://huggingface.co/ARTPARK-IISc/SraVaani-0.5-live)
- SraVaani-0.5-live Telugu WER (avg over Vaani, RESPIN, FLEURS, IndicTTS, CommonVoice, Gramvaani, Kathbath, MUCS test sets): 34.6 (0ms), 33.6 (80ms), 31.4 (480ms), 30.3 (1040ms) vs 25.1 for offline SraVaani-1.0; Hindi 22.1 / 21.3 / 19.3 / 18.0 vs 12.4 offline. — [HF: SraVaani-0.5-live](https://huggingface.co/ARTPARK-IISc/SraVaani-0.5-live)
- SraVaani-0.5-live limitations stated on card: causal normalization hurts first words of a stream; Latin-script code-switching can inflate WER against single-script references; lowest-latency settings trade noticeable accuracy. — [HF: SraVaani-0.5-live](https://huggingface.co/ARTPARK-IISc/SraVaani-0.5-live)
- SraVaani-1.0 (offline sibling): ~430M, FastConformer hybrid TDT-CTC, MIT, gated, 65 languages; pretrained from scratch on 31,255 h VAANI speech, fine-tuned on ~31,270 h labelled speech; WER Hindi avg 12.4 (CommonVoice 12.7 / Fleurs 10.9 / GramVaani 20.93 / IndicTTS 9.1 / Kathbath 9.1 / MUCS 14.6 / RESPIN 10.8 / Vaani 10.8), Telugu avg 25.1 (Fleurs 23.1 / IndicTTS 20.9 / Kathbath 21.3 / MUCS 26.4 / RESPIN 25.4 / Vaani 33.5), English avg 14.8 (Vaani only); ONNX export and sample script "linked externally"; fine-tuning checkpoints need a separate access request. — [HF: SraVaani-1.0](https://huggingface.co/ARTPARK-IISc/SraVaani-1.0)
- SraVaani 1.0 paper (arXiv 2608.08235, 8 Aug 2026, v2 12 Aug): three-stage training (contrastive SSL on 31,255 h unlabelled; audio-image alignment; fine-tune with hybrid TDT-CTC on 31,263 h labelled from 24 public datasets). Paper page does not state model size, streaming, or weights license. — [arXiv 2608.08235](https://arxiv.org/abs/2608.08235)
- ARTPARK-IISc org also lists Vaani-FastConformer-Telugu / -Hindi / -Odia / -Kannada (Apr 2026), whisper-large-v3-vaani-{hindi,telugu,odia} (listed as 2B), Vaani-LID_v0. — [HF org page](https://huggingface.co/ARTPARK-IISc)
- Vaani-FastConformer-Telugu: NeMo, loaded as `EncDecRNNTBPEModel` (RNN-T + BPE), MIT tag, gated, trained on ARTPARK-IISc/Vaani, no WER, no params, no statement of cache-aware/streaming. — [HF: Vaani-FastConformer-Telugu](https://huggingface.co/ARTPARK-IISc/Vaani-FastConformer-Telugu)
- NVIDIA Nemotron 3.5 ASR streaming 0.6B (released 2026-06-04): FastConformer-CacheAware-RNNT, 24-layer encoder, language-ID prompt conditioning (128-dim one-hot broadcast over time, concatenated with encoder output); chunk sizes 80/160/320/560/1120 ms via `att_context_size=[56,N]`, N in {0,1,3,6,13}; 40 locales; **Hindi is "transcription-ready"; Telugu and en-IN are not listed**; code-switching not discussed; license OpenMDW-1.1, "ready for commercial use". — [HF: nemotron-3.5-asr-streaming-0.6b](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b)
- Nemotron 3.5 fine-tuning: NVIDIA states full fine-tune (not LoRA; author says LoRA not currently supported) from base via `init_from_nemo_model`, each clip needs `target_lang` tag and punctuated/cased transcripts; worked example used ~2,000 h (Greek+Bulgarian; later ~2,300 h pool) with Greek FLEURS WER 35->24 and Bulgarian 22->15 at 80ms; blog says nothing about adding a new tokenizer/tokens and gives no GPU spec; companion notebook is nvidia-riva/tutorials asr-finetune-nemotron-3.5-asr-streaming-prompt.ipynb. — [HF blog: fine-tuning Nemotron 3.5 ASR](https://huggingface.co/blog/nvidia/fine-tuning-nemotron-35-asr)
- NVIDIA staff on the Nemotron 3.5 discussion board (Jun 14): tokenizer/architecture can take new languages via fine-tuning; "tracking demand for Indic languages"; "expanding to more Indic locales is on the roadmap"; no dates; Telugu never mentioned. — [HF discussion #12](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b/discussions/12)
- Cache-aware FastConformer recipe (Noroozi et al., arXiv 2312.17279): limit look-ahead and past context, add activation cache so each frame is processed once; works with CTC and RNN-T; hybrid CTC/RNNT shares one encoder; **training with several latency settings yields higher accuracy than a single-latency model and one model can serve multiple operating points**. — [arXiv 2312.17279](https://arxiv.org/abs/2312.17279)
- NVIDIA parakeet-unified-en-0.6b (2026): single 600M FastConformer-RNNT trained jointly in offline and streaming mode with mode-consistency loss (arXiv 2604.19079); but current pipeline is *buffered* streaming (recomputes left context), min latency 160 ms; English only; NVIDIA Open Model License. — [HF: parakeet-unified-en-0.6b](https://huggingface.co/nvidia/parakeet-unified-en-0.6b)
- AI4Bharat built a cache-aware streaming Nemotron-600M fine-tune for an unreleased Bhili model: ~200 h of Bhili data, encoder trained on seven attention-context configurations simultaneously (e.g. `att_context_size=[96,7]`), multisoftmax checkpoint selected by `target_lang`; MIT tag but "unreleased research model", gated case-by-case. This is a published-by-an-Indic-lab proof that ~200 h is enough to produce a usable cache-aware streaming Indic model from the Nemotron base. — [HF: ai4bharat/bhili-asr-nemotron-600m](https://huggingface.co/ai4bharat/bhili-asr-nemotron-600m)
- Typhoon ASR Real-time (Thai): 114M FastConformer-Transducer, built on nvidia/stt_en_fastconformer_transducer_large, ~10,000 h Thai, CC-BY-4.0; precedent for retargeting a small FastConformer-Transducer to a new language for real-time use (card gives no streaming recipe; paper PDF text could not be extracted). — [HF: typhoon-asr-realtime](https://huggingface.co/typhoon-ai/typhoon-asr-realtime); [arXiv 2601.13044](https://arxiv.org/pdf/2601.13044)
- I found no official AI4Bharat streaming/cache-aware IndicConformer release; a GitHub issue (May 24, 2026) requests a 30M lightweight model; AI4Bharat's models page describes a "30M-parameter" conformer for real-time ASR (undated, unconfirmed to be released). — (search summary) [AI4Bharat IndicConformerASR issues](https://github.com/AI4Bharat/IndicConformerASR/issues); [AI4Bharat models page](https://models.ai4bharat.org/)
- Vendor marketing claims "native streaming via RNNT decoder" for the existing IndicConformer; unverified. — (search summary) [Indic-STT repo](https://github.com/shivsinghin/Indic-STT)

### Inferences
- Cheapest credible path A (lowest risk, license-clear): Nemotron 3.5 ASR streaming 0.6B -> fine-tune on Telugu (+ Indian-English + Hindi-English/Telugu-English code-switch) with a new `target_lang` head. It is already cache-aware, already trained at multiple lookaheads, Hindi already ~6.8-8.1 FLEURS WER, and the fine-tune recipe is public. Open risks: no published Telugu script coverage in its tokenizer (Nemotron model card gives no tokenizer details and NVIDIA's blog does not describe adding tokens; the Bhili precedent suggests Indic scripts are handled, but Telugu-script tokenization must be tested), GPU memory for full fine-tune of 600M on a 24GB A10G (not documented; likely feasible with bf16 and small batch but unverified), LoRA unsupported.
- Path B (Indic-native): take an offline Indic FastConformer (SraVaani-1.0 / Vaani-FastConformer-Telugu / IndicConformer 120M per-language) and run the NeMo cache-aware multi-lookahead fine-tune (chunked attention masks + causal convs + cache), per Noroozi et al. SraVaani-0.5-live is evidence that ARTPARK already did exactly this for a 430M model, and its numbers quantify the streaming penalty: ~+5 absolute WER on Telugu and ~+6 on Hindi at 480ms vs. offline. Risks: gated weights, MIT tag but need to confirm gating terms/commercial use in writing, training from the 0.5-live checkpoint is the shortest route if access is granted.
- Expect a streaming penalty of roughly 4-6 WER abs. on Indic at 0.5s lookahead from the one hard datapoint available (SraVaani live vs 1.0); NVIDIA's own English/Hindi data shows a smaller gap (Hindi FLEURS 6.81 at 1.12s vs 8.13 at 80ms).

### Gaps
- SraVaani-0.5-live card is internally inconsistent: it says streaming WER "is reported for Hindi only" yet tabulates Telugu; and the card says ~430M params but the fp16 TorchScript is ~900MB (consistent with ~430M x 2 bytes, so fine). The CTC-only export means no RNNT/TDT head in the live model.
- Whether SraVaani-0.5-live / Vaani-FastConformer-* gating permits commercial use and fine-tuning: cards say MIT tag + "agree to share contact information"; no separate terms were readable.
- No measured CPU RTF for any Indic streaming FastConformer was found.
- AI4Bharat/Bodhan "Indic-Transcribe-lite" (the real-time sibling mentioned on the Flex card) could not be fetched (HTTP 401); its params/license/streaming status are unverified (see Q2).

## Q2. Candidate catalogue: params, architecture, languages (Telugu?), license, streaming, runtime support, published WER

### Takeaway
Only NVIDIA Nemotron 3.5 streaming, SraVaani/Vaani FastConformers, IndicConformer, and (with caveats) Bodhan Indic-Transcribe are both Telugu-capable and FastConformer-class. Qwen3-ASR, Voxtral Realtime, Parakeet-Indic, Kyutai, Moonshine, Granite, SenseVoice, FireRed have Hindi at best and no Telugu. Whisper and Omnilingual and MMS cover Telugu but are not natively streaming (and MMS is CC-BY-NC).

## Q3. Best-fit shortlist (3) and disqualified options

### Takeaway
Recommended bake-off: (1) NVIDIA Nemotron 3.5 ASR streaming 0.6B + Telugu/Indic-English fine-tune; (2) ARTPARK SraVaani-0.5-live / SraVaani-1.0 (or Vaani-FastConformer-Telugu) -- Indic-native FastConformer, streaming-ready or convertible, 430M; (3) AI4Bharat IndicConformer (600M multi, or 120M per-language) with cache-aware streaming fine-tune as the small/fast variant. Most large "attractive" options fail on Telugu, size, streaming or license.

### Cited Findings (basis for ranking)
- Pick 1 evidence: native cache-aware streaming with 80ms-1.12s chunks, 600M, OpenMDW-1.1 "ready for commercial use", Hindi 6.8-8.1 FLEURS WER, fine-tunable, no Telugu yet. — [HF: nemotron-3.5-asr-streaming-0.6b](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b)
- Pick 2 evidence: Telugu offline 25.1 avg / streaming 30.3-34.6 avg WER, Hindi 12.4 offline, 430M, MIT-tagged but gated, TorchScript export only; code-switch tokenizer includes Latin. — [HF: SraVaani-0.5-live](https://huggingface.co/ARTPARK-IISc/SraVaani-0.5-live); [HF: SraVaani-1.0](https://huggingface.co/ARTPARK-IISc/SraVaani-1.0)
- Pick 3 evidence: MIT-tagged, Telugu/Hindi covered, 120M per-language model runs ~16x real-time on CPU in Q8 GGUF (community), IndicConformer outperformed by Indic-Transcribe on Voice of India (Telugu 16.2 vs 11.4-13.1; Hindi 6.5 vs 3.5-4.1) but is far smaller. — [HF: indic-conformer-600m](https://huggingface.co/ai4bharat/indic-conformer-600m-multilingual); [GGUF card](https://huggingface.co/Singla0009/IndicConformer-GGUF); [Indic-Transcribe Flex card](https://huggingface.co/bodhan-ai/indic-transcribe-flex)
- Disqualified/de-prioritized:
  - MMS-1B-all: CC-BY-NC 4.0 (non-commercial), 1B, no streaming. — [HF: mms-1b-all](https://huggingface.co/facebook/mms-1b-all)
  - Voxtral Mini 4B Realtime: Apache 2.0 and excellent streaming Hindi, but ~4B params (3.4B LM + 970M encoder), >=16 GB GPU recommended, no Telugu (13 languages). — [HF](https://huggingface.co/mistralai/Voxtral-Mini-4B-Realtime-2602)
  - Qwen3-ASR 0.6B/1.7B: Apache 2.0, streaming, Hindi supported (FLEURS error 19.1/17.2), but Telugu not in 30-language list; Hindi quality worse than Indic-native; streaming mode GPU-serving oriented. — [tech report](https://arxiv.org/html/2601.21337)
  - Parakeet-TDT-0.6B-v3 / Canary-1B-v2: European languages only; Parakeet Indic 1.1B: 1.1B params, bn/en/hi/ta only, community-license terms. — [HF](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3); [NGC](https://catalog.ngc.nvidia.com/orgs/nvidia/-/collections/parakeet-1-1b-rnnt-multilingual/-)
  - Indic-Transcribe Core/Flex: Telugu-capable and best published Telugu (11.4/13.1 WER Voice of India) but 1.2B, offline (max 30 s windows), "Indic Open Model License v1.0" with unread terms, base canary-1b-v2 terms also apply; lite (real-time) variant unverified. — [HF: Flex](https://huggingface.co/bodhan-ai/indic-transcribe-flex)
  - Kyutai STT: en/fr only (1B). — [HF](https://huggingface.co/kyutai/stt-1b-en_fr)
  - Moonshine: English MIT models; non-English legacy non-streaming models are non-commercial; no Hindi/Telugu evidence. — [GitHub](https://github.com/moonshine-ai/moonshine)
  - Granite Speech: no Hindi/Telugu. SenseVoice/FireRed: no Hindi/Telugu. — (search summary) [Granite blog](https://huggingface.co/blog/ibm-granite/granite-4-speech); [SenseVoice](https://github.com/FunAudioLLM/SenseVoice)
  - Whisper (any size) as base: not natively streaming; retrofit via SimulStreaming/LocalAgreement with no Indic streaming benchmark; large models exceed CPU budget. — (search summary) [WhisperLiveKit](https://huggingface.co/spaces/langtech-innovation/WhisperLiveKit/blob/2ba48bcbf436dae9ebf126cb7df6c960a8bd8cc2/README.md)
  - Omnilingual ASR: Apache 2.0, Telugu CER 6.5 on 7B LLM; CTC-300M is edge-sized but non-streaming, <40 s inputs, fairseq2 stack; keep as SSL-encoder/ CTC fallback. — [GitHub](https://github.com/facebookresearch/omnilingual-asr)
  - Sarvam Saaras/Saarika: API-only (no open weights found). — (search summary) [Sarvam docs](https://docs.sarvam.ai/api-reference-docs/getting-started/models)
  - Zipformer/sherpa-onnx: best CPU tooling but no Indic checkpoint; would require pre-training an Indic model from scratch (impractical on one A10G) or fine-tuning the English streaming zipformer (precedent: 277 h Indian English). — [HF](https://huggingface.co/Akshatkasera007/STT-streaming-zipformer-indian-en)

### Inferences
- Licensing priority: Nemotron 3.5 (OpenMDW-1.1) is the only top candidate where the card explicitly says "ready for commercial use". For the Indic-native models the card tags say MIT but are gated, and a community repo says CC-BY-4.0 for IndicConformer derivative; a written confirmation from AI4Bharat/ARTPARK is needed before commercial shipping.
- Parakeet-TDT-v3 CC BY 4.0 and Typhoon CC-BY-4.0 imply attribution is required for derivatives; OpenMDW-1.1 terms (including derivative-model terms) should be read by counsel (text not retrieved).
- For a three-way bake-off the primary metric should be streaming Telugu/Hindi/Indian-English WER at 160-560 ms lookahead on in-house code-switched test data, since published numbers use mismatched benchmarks.

### Gaps
- Exact OpenMDW-1.1 text, NVIDIA Open Model License derivative clauses, Indic Open Model License v1.0 text and the MIT-gated terms of ARTPARK/AI4Bharat were not retrieved.
- No published code-switched Hindi-English or Telugu-English WER for any candidate except qualitative notes (SraVaani Latin-script caveat; Indic-Transcribe Hinglish mixed mode).

## Q4. Key published Hindi/Telugu/English numbers (for reference, with benchmark names) and CPU/edge runtime status

### Takeaway
Published numbers are not comparable across vendors (different normalizations, benchmark versions). Indic-native offline: SraVaani-1.0 Hindi 12.4 / Telugu 25.1 avg; streaming SraVaani-0.5-live Telugu 30-35. NVIDIA Nemotron 3.5 Hindi FLEURS 6.8-8.1. CPU evidence is thin: only GGUF/ONNX community exports of IndicConformer (RTF ~0.06) and sherpa-onnx int8 zipformer (RTF 0.035).

### Cited Findings
- Nemotron 3.5 streaming: FLEURS English WER 9.43 (80ms) -> 7.91 (1.12s); Hindi 8.13 -> 6.81 (LangID prompt) and 11.47 -> 8.23 (auto-detect). Vaani Hindi 20.2. — [HF](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b)
- SraVaani-1.0 per-benchmark Hindi/Telugu WER (above); IndicConformer-600M Hindi 13.2 on Vaani-Benchmark-V1.0. — [SraVaani-1.0](https://huggingface.co/ARTPARK-IISc/SraVaani-1.0); [IndicConformer 600M](https://huggingface.co/ai4bharat/indic-conformer-600m-multilingual)
- Omnilingual 7B LLM-ASR: Hindi CER 3.6, Telugu CER 6.5, English CER 3.0 (benchmark unnamed in CSV). — [CSV](https://raw.githubusercontent.com/facebookresearch/omnilingual-asr/main/per_language_results_table_7B_llm_asr.csv)
- Qwen3-ASR FLEURS Hindi 19.12 / 17.15. Whisper large-v3 FLEURS Hindi 28.87 (per Voxtral paper). Voxtral Realtime FLEURS Hindi 2.4-5.6 (card). — [Qwen3-ASR](https://arxiv.org/html/2601.21337); [Voxtral paper (search summary)](https://arxiv.org/pdf/2507.13264); [Voxtral card](https://huggingface.co/mistralai/Voxtral-Mini-4B-Realtime-2602)
- Voice of India (Indic-Transcribe's own benchmark): Telugu / Hindi WER: Core 11.4/3.5, Flex 13.1/4.1, Saaras V3 13.5/3.8, Indic Conformer 16.2/6.5, Gemini 3 Pro 24.6/9.3. — [Flex card](https://huggingface.co/bodhan-ai/indic-transcribe-flex)

- Earlier Hindi accent benchmark LAHAJA: Indic-trained Hindi ASR 14.3-19.4 WER; commercial APIs beat massively multilingual open models. — (search summary) [LAHAJA](https://arxiv.org/pdf/2408.11440)

### Inferences
- A 600M-param FastConformer-RNNT int8 on laptop CPU should be faster than real-time (120M model already 16x on CPU in Q8; encoder cost scales roughly with params), but no measured CPU RTF for the 600M streaming Nemotron was found; this must be benchmarked (ONNX export of cache-aware encoder is nontrivial; NeMo-Speech.cpp GGUF is the only first-party-adjacent CPU path found).
